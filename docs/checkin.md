# 累计签到基础版

规则确认日期：2026-11-16。

- 累计第1、8、15天获配色奖励，此后每7个累计签到日一份。不按周计算、不要求连续、不在元旦重置。
- 首批56款非免费配色，固定清单在 `cloudfunctions/atlas-checkin/rewards.json`。第56个奖励节点为累计386天，不能为了凑一年修改节奏。
- 每个里程碑固定对应一款奖励，达标后直接领取；未领取机会保留。云端以里程碑日作为领奖幂等键，不因重复点击消耗下一份奖励。
- 配色获得后进入收藏，不自动加入首页配色位，不自动切换。首页列表最多6款，使用中不可移除。
- 印章奖励从累计第2天开始，此后每7天一枚：2、9、16……415，共60枚，与配色奖励并行，已达标可补领。完整规则与维护方式见 [旅途印章](stamps.md)。

奖励顺序按色系和深浅穿插后固定，不在用户打开页面时重新随机。已领取奖励保留。唯一维护源为云端 rewards.json；运行 scripts/checkin/sync-rewards.cjs 同步客户端，--check 验证清单一致，不改变已有云端用户记录。

## 数据与安全

- 集合 `mini_atlas_checkins`，权限为“所有用户不可读写”。用户已确认创建完成；仅 `atlas-checkin` 云函数管理访问。
- 身份以可信云调用的APPID、OPENID生成摘要ID；忽略客户端日期、天数和用户ID。
- 北京日期由服务端UTC时间加8小时计算。每用户一个独立文档，签到计数与奖励发放均在事务中更新；无需每日全量扫描。
- 不记录航班、不修改原记录，不使用定时器替用户签到。服务开关为 deployment.json.enabled，可用环境变量 ATLAS_CHECKIN_ENABLED=false 紧急关闭。
- 状态带revision；客户端拒绝较旧响应覆盖新奖励。缓存只用于展示，不能作为服务端领奖依据。
- 账户分区缓存签到状态与拥有配色；换设备后在收藏／签到页恢复云端权益。首页候选列表仍是本机账号偏好，不宣称已跨设备同步。

## 资源与页面

- 收藏页右上角提供签到入口；签到页展示累计天数与滚动30格奖励预览。已签到的普通天数和已领取奖励的天数移出，未领取的达标奖励保留，未来天数补足30格。点击奖励格弹窗领取，成功后展示独立确认弹窗。
- 配色复用现有固定示例；印章使用小图总览和两个按需高清资源分包，海报直接矢量绘制，不读取云存储图片。
- 同账号签到状态请求合并：收藏页后台刷新复用30分钟缓存，签到页复用5分钟缓存；跨北京日期自动失效。读取失败冷却1分钟，手动重试立即访问服务端；实际签到／领奖不走缓存。
- 配色已拥有状态与签到台账联动；未接入广告、支付、补签或积分。

## 验证边界

已增加跨年、漏签、北京时间边界、同日重复签到、重复领奖、未达标领奖、固定奖励、防止客户端篡改奖励、伪造身份参数及未启用服务不访问数据库的测试。

部署不等于真实微信账号验收。上线前仍需在开发版由用户操作：签到→领取一款→收藏显示已拥有→主动添加到首页候选列表。不得用模拟测试宣称该链路已经真机通过。
