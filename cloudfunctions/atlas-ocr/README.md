# 小程序图片识别

复用网页版的截图解析器与 AirportSearch（含机场别名数据），Tesseract.js 5.1.1 在独立微信云函数运行，语言包随 npm 依赖部署，不在运行时请求公共 CDN。前端位于 airport-picker 分包，不改变网页版。

环境：cloud1-d5g931htr9ee8f18c；使用已有仅管理端可读写的 mini_atlas_drafts 集合，ocr-quota- 前缀与航班文档隔离。每个微信用户每天最多申请 20 次识别，票据有效 5 分钟且只能使用一次，过期票据在后续请求清理，不为每张图片建立持久文档。只接受本人票据路径及当前环境的图片；上限 4 MB；识别文字不写数据库。

建议内存 512 MB，超时 60 秒，单实例并发 1。config.json 的配置需要部署后在控制台核对，避免平台保留默认超时。图片在识别结束或错误时由服务端删除，客户端也在 finally 删除；强制退出或平台强制终止时可能残留临时文件，可在云存储为 atlas-ocr/ 设置定期清理。勿为此放宽整个存储桶的读写权限。

用户在地图的“航班数据”或航班列表点击图片识别，选择相册/拍照，逐条核对、补齐缺失字段，再确认导入。未确认不写航班，模糊机场不自动猜测；按现有规则合并去重，自动保存到微信账号。

识别引擎为开源组件，不需要第三方 OCR API Key；云函数计算、云存储和流量使用现有云开发额度，不承诺永久免费。发布前需按实际调用更新小程序隐私保护指引中的相册/拍照图片用途。不要声明图片始终只在手机处理。

长截图：前端保留较高的截图宽度，最多 900 万像素、12000 像素高；若压缩后宽度过低则要求用户分批截图。服务端对超过 2400 像素高的图片解码为 RGBA，每 1800 行识别一次，上下各保留 160 行上下文，同一次调用复用一个 OCR worker。按文字行中心位置归属合并，跨段日期在完整文字上统一解析；不以相同文字去重，避免错误删除不同航班的重复内容。图片和文字的大小上限仍生效，超限不返回残缺前缀。长图可能更慢，仍使用已设置的 60 秒超时和 512 MB 内存。

检查：node --test miniprogram-tests/*.test.cjs。除文本解析、校验和服务端身份隔离测试外，还应在微信真机用截图验收识别耗时、中文准确率、后台/退出与清理。
